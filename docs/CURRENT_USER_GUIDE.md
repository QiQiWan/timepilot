# v0.37.7 当前使用说明：统计发现与证据

在项目的「分析工作台 → 统计图表 / 数据一览」选择源数据、版本和筛选条件。页面展示由同一 DuckDB 视图计算的指标与图表，在「这批数据的主要发现」展开可查看每一结论对应的数值、字段路径及来源指纹。点击「导出证据报告」可以获取同一筛选范围的 Markdown，浏览器会核对服务器返回文件的 SHA256。改变筛选或数据版本后，旧结果不再复用。

在「自动特征」点击候选图表，看到分布或设备分组的实际数值结论。只有原始特征与新特征单位兼容且桶均值均可计算，才显示二者的数值差异。技术口径位于展开区。

在「成果与评价」选择已完成的正式计算。只有标签、物化产物 SHA256、字段契约和每个外层验证折均核验通过时，才会显示原始字段与两个特征方案的模型对照。负改善意味着验证折上模型表现退化。无标签会显示「尚无可靠的监督评价证据」，不会宣称收益。

更多安装、项目、数据管理与 BI 使用详见下文。正式物理验收仍需真实 DuckDB/Parquet 和已安装的 Google Chrome。

# v0.34.0 数据分析与特征工程入口

项目内打开 **数据分析**，选择已发布数据和版本。系统优先复用现有画像；新数据会自动建立受控后台画像任务，待完成后展示字段统计、缺失信息和图表，随后提供进入特征工程的建议。字段图表只使用当前版本经源 SHA256 验证的计算结果。用户也可进入 BI 进行完整数据探索。

特征工程中，用户检查候选质量、查看真实计算图表、确认并保存特征配方，再根据适用的监督验证协议查看模型对照。每项特征的训练折入选频率只在同源评价存在时显示，不能视为上线收益。分析报告可点击“保存报告版本”形成不可覆盖的 Markdown/SHA256 归档，旧版本继续保留。

遇到后台计算中断，服务端 Worker 按租约重新领取；过期 Worker 的迟到提交不会覆盖新产物。只有存在真实失败作业时，才展示可执行的重试入口。关闭大模型后基础统计与规则引导可继续运行。

有关详细技术限制和测试步骤参阅 [v0.34.0 验收报告](FEATURELAB_V0340_INTEGRATED_RELEASE_REVIEW.md)。

# TimePilot v0.33.3｜特征分析用户指南

## 1. 从一份数据开始

进入项目 → 数据管理，导入 CSV/XLSX/Parquet 并发布数据资产；保留源文件和来源版本。然后进入项目 → 特征工程，在顶部选择数据及版本。可直接使用“自动发现特征”，也可以从分析目标下拉框选择“异常与波动”“分类识别”等任务；补充要求是可选的。点击“自动分析特征”。系统依次执行字段检查、全量画像、受限候选生成、真实数值预览、质量筛选与证据解释。任务可刷新和恢复。无大模型 API 时沿用确定性规则完成基础分析。

## 2. 如何判断结果

“建议保留”只表示通过缺失率、有效值覆盖和变化性等质量门槛，不代表模型预测贡献或业务因果关系。页面左侧可以按质量状态筛选候选，点击“查看”后，右侧直接呈现实测数值分布、分类分组、时序曲线或设备差异图（按适用条件显示）。图表按当前数据版本计算；时序图只显示有序记录预览，并明确标注。候选多选时，切换过滤条件不会丢失隐藏的已选项。保存选择后，明确确认并发起正式计算。正式物化会生成新 Parquet 资产和 SHA256，不修改原始数据。

## 3. 需要质量分类或预测时

特征工程工作台“成果使用”区域的“模型效果对照（可选）”允许在正式生成特征时绑定监督任务。首先在数据管理确认实际标签字段，并按业务数据选择验证协议：

- **独立静态回归**：K 折验证，用户须确认样本独立、所有输入字段在预测决策时可用；字段间变换仅支持逐行算子。
- **独立静态二分类**：按 0/1 标签使用分层 K 折，正负样本需满足各折最低数量；分类阈值 0.5 仅用于固定基线对照。
- **同一设备或批次有多条记录**：必须确认设备/批次 ID，采用分组 K 折；同一实体不得同时出现在训练与验证中。
- **工业时间预测**：确认设备 ID、真实事件时间、过程实际可用时间、预测决策时点、质量标签和**独立的标签可用时间**，按时间顺序滚动验证。时间解析及所属时区必须核实。

系统按同一折、同一模型比较原始字段、全部特征和折内筛选特征。缺失填充、缩放及筛选均以外层训练折为依据。模型评价还会输出筛选频次、折间 Jaccard 稳定性与验证折的实际训练行哈希。未满足条件仍可保存探索分析，但不会显示预测收益结论。所有正式结果必须与同一 Parquet 产物的 SHA256 相匹配。

数值 `Time=1,2,...` 在未确认原始业务时间意义前只能作为**记录顺序**，支持行窗口特征，不能代表真实秒/小时或按时长计算的窗口。禁止将过程测点 `available_at` 直接替代标签可用时间。

## 4. 模型与 Agent 怎样介入

配置可用模型后，系统允许模型辅助判断目标、数值字段与模板、已实测合格候选的优先级和证据摘要；模型不能自行生成原始数据值或预测准确率，也不能调用保存/物化/发布、任意 SQL/Python 或跨项目权限工具。模型没有配置、超时、返回额外字段或受限数据禁止外发时，系统自动回退规则计算。执行记录可在自动分析界面展开查看。

## 5. 查看 BI 和下载报告

点击“在 BI 查看特征”，系统先核验当前源资产、已保存特征集和完成物化的 Parquet ID/SHA256，然后才打开 Perspective。实际浏览器加载成功后会将双面板**客户端声明**保存为证据；仍须另行运行独立浏览器验收。

下载 Markdown 报告，也可点击“导出同源核验 JSON”获得单独的机器可读证据；报告接口返回的结构化结果还包含 `report_sha256`（原始 UTF-8 字节哈希）、`delivery`（同源清单）。报告里的源 SHA、配方 SHA、正式产物 SHA、模型评价 ID、BI 回执都可以追溯。缺失任一真实计算或验收证据时应显示“待验收/阻断”，不能解释为上线批准。

## 6. 在 Mac 上启动和排查

先备份 `TIMEPILOT_HOME`，随后在源码目录运行：

```bash
bash TIMEPILOT.sh db-check
bash TIMEPILOT.sh source-check
bash TIMEPILOT.sh accept feature-lab-v0324 --mode offline
bash TIMEPILOT.sh
```

安装不会删除原项目库；Schema 35 兼容 v0.32.1。首次构建 Perspective 需要 Node 24、npm 和真实的前端依赖；只有完整发行包内含通过校验的 JS/WASM 时才能离线直接复用。生产级验收还需要真实质量标签、独立时间截断规则、企业权限验证、macOS Chrome 浏览器和人工作业复核。

## 7. v0.32.4：顺序、设备和可解释的自动化

在数据管理中可将 `Time=1,2,...` 一类数值列确认成 `order_index`，然后确认实际设备或批次分组键；全量数据存在空键、设备内重复序号时，系统将禁止生成窗口特征，要求先校核数据。未确认排序或设备键时，自动工作台仍可生成无需时间顺序的逐行数值候选。不要把导入行号默认当成设备的实际时间。

“预测不良率”会优先建议回归，“故障是否发生”会建议分类；系统只给出方向建议，监督任务仍要明确确认标签与可用时间。20 万至 200 万行采用预算限制的后台全量计算，超过 200 万行会提示明确分区方案。自动分析结束后，勾选人工确认即可一次提交草稿和物化；不会自动审批和发布。

外层训练折反馈仅在真实产物 SHA256 与监督评价核验一致后展示；“候选有潜在收益”意味着值得人工复核，不能当作生产效果证明。高级 tsfresh/Featuretools 只提供受控推荐，需要单独审核和授权，不会自动对外传输源数据。

## v0.32.4：历史配方审计与任务状态

特征资产页将突出仍按导入行号执行的旧窗口配方，正式发布会被阻断。新手工窗口须先确认排序和设备键。自动分析结果显示来自任务状态的下一步操作；保留意见不等于模型性能收益。

## 8. v0.33.1 工作台页面与刷新恢复

页面由数据和版本选择、任务状态、候选列表与详情、成果使用四部分组成。分析完成后直接显示结果；算法日志及哈希放在可展开的运行详情中。选择候选、筛选条件和图表类型后，系统会在 URL 中保存这些状态；刷新或按浏览器后退可恢复对应记录。数据版本或数据资产发生变更时，旧候选和图表不再作为当前结果使用。

如图表显示“不适用”，请检查类别字段、设备键或记录顺序是否已被确认。如果图表超出 200 万行计算预算，请先做合理分区。需要验证新特征对模型预测的贡献时，必须继续完成正式物化和同源模型评价；仅通过质量检查不代表实际提升预测效果。

## v0.33.3 - server-side continuation and recovery

Once analysis begins, the embedded FeatureLab Worker continues completed stages even when the tab is closed. The workbench status Refresh button now only reads `GET /analysis/sessions/{sid}`. For a failed compute stage, the action Retry Failed Stage posts the last session revision and requeues only failed jobs. It cannot repair corrupted successful artifacts or bypass source/contract changes. After changing the input asset, version or field contract, start a new analysis; historical reports are explicitly marked stale. The model is optional and errors fall back to deterministic rule operations; model-authored publishing and unrestricted tools are blocked. BI open and evidence export require a matching verified artifact identity/SHA256. A Perspective client receipt is not an independent browser acceptance. See [v0.33.3 review](FEATURELAB_V0333_RELEASE_REVIEW.md) for tests and remaining Mac acceptance steps.

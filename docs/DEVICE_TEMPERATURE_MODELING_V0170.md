# TimePilot v0.17.0｜设备温度预测与通用数据建模工作台

## 1. 本版交付范围

本版打通已发布的**项目通用数据资产**与现有月、日、小时级单目标预测引擎。在同一份数据上，用户可以多次进入 BI、调整筛选、创建独立的建模草稿、冻结训练输入、运行模型及克隆方案复现实验。所有预测模型运行均保留项目、资产版本、视图、筛选、字段映射、算法配置、数据集和运行编号。

入口：**项目 → 数据管理 → 通用数据资产 → 正式 BI → 从当前数据建立模型**。项目的「模型管理」提供草稿续办、回到原 BI、复现实验与运行查看。

原始数据始终保持不可变。保存图表时的样本上限、排序、透视和聚合均不会替代训练明细行集。用户必须确认全量行级筛选范围才能提交草稿。

本版运行范围：`frequency = h / D / MS`，一个目标、可选多个实体、使用**目标自身历史**；可执行基线包括 `last_value`、`moving_average` 及兼容频率的其他已安装插件。分类、异常检测、机理学习建议可以显示，但其运行适配仍按插件能力单独开放。分钟级、秒级和纯整数时间步不会未经声明直接改成小时级。

## 2. 以设备温度为例的页面设计

### 第一步：识别与推荐

系统读取发布后不可变 CSV 的原始全部列，遍历全量行数，并从全表确定性均匀抽样最多 2,400 行用于字段画像。展示：原始总行数、抽样行数、字段清单、推荐角色、置信度和具体理由。`Time/A1/A2` 一类编码列保留原始名称，不会自动虚构设备温度、采样单位或时间单位。

示例源列（仅用于说明，上传时按真实字段名识别）：

| 原始字段 | 自动建议 | 需要用户确认的事项 |
| --- | --- | --- |
| `采集时间` | 日历时间 | 时间为记录时刻，时区 `Asia/Shanghai` |
| `设备编号` | 实体标识 | 每台设备独立序列，不能混合排序 |
| `温度(℃)` | 数值预测目标 | 单位 °C，目标对应实际传感器的测量位置 |
| `气压(kPa)` | 其他数值指标 | 本版仅保留，不作为多变量输入 |
| `维护事件` | 事件 | 确认维修发生时刻；本版不作为预测特征 |
| `available_at`（如有） | 数据可用时间 | 是否确为在线算法能读取该值的时刻 |

候选任务标记为「可进入审核」「需要适配」或「缺少算法插件」。可进入审核不等于已经通过数据连续性、历史长度和可用时间检查。

### 第二步：字段映射与评估参数

默认展开：任务名称、预测目标、目标物理单位、时间列、设备列、采样频率、预测跨度、任务类别、时区、数据可用时间方式。高级回测设置收进折叠面板，只在需要时打开。

建议初始值（适用于已确认为**每小时采样**的温度序列）：

| 参数 | 建议值 | 解释 |
| --- | --- | --- |
| 时间列 | `采集时间` | 必须是可解析的真实日期时间，整数 1…N 不自动视为小时 |
| 实体列 | `设备编号` | 每个设备单独校验连续性和评估结果；单设备文件可留空 |
| 目标列与单位 | `温度(℃)`、`℃` | 只预测经确认的这一列；单位从表头建议，用户可核对或修改 |
| 时区 | `Asia/Shanghai` | 用 IANA 时区解析本地时间，存储的规范化结果使用 UTC |
| 任务类别 | `equipment_state` | 设备状态预测；销量、需求类可以选择 `demand_forecast` |
| 预测频率 | `h` | 小时级；系统按完整数据逐实体验证实际间隔 |
| 预测步长 | 3 | 未来 1/2/3 小时的温度 |
| 可用时间 | 真实 `available_at` 或已确认的发布延迟 | 不能默认为「采集时就可用」；0 天延迟也要明确确认 |
| 验证窗口 | 3 | 在最终独立测试期之前进行 3 个滚动起点回测 |
| 最少历史 | 24 个时间点 | 逐设备检查，实际门槛还受插件和评估窗口约束 |
| 主指标 | MAE | °C，利于工程师判断绝对误差 |
| 模型 | 最近值、移动平均 | 简单确定性基线，不把未使用传感器冒充模型输入 |

表单在选择“源可用时间列”时显示该列映射，选择“声明延迟”时显示延迟天数；未确认时禁止批准。用户无需上传第二份预测格式文件。

### 第三步：数据预检查、确认与运行

显示下列关键数字：源记录数、按已冻结筛选选中的记录数、有效记录数、实体数、时间覆盖起止、每实体最少记录数、可执行插件及阻断原因。

按序完成：**保存建模方案 → 数据预检查 → 用户确认 → 生成训练数据 → 提交运行 → 模型管理查看**。草稿支持重开，版本变更通过乐观并发修订号检查。数据集生成后冻结草稿；更改字段或评估方案须新建草稿。已完成的草稿可以“复现实验”，生成独立待审核副本，复用相同源版本及筛选，再产生新数据集、运行编号和可比较结果。

## 3. 输入字段校验和适配规则

1. **时间与实体**：`(设备编号, 采集时间)` 不允许重复；排序后每台设备必须严格连续。含无法解析时间、混合时区或跳时的数据拒绝入模。日历小时与本地时区按 UTC 保存；不得以字符串顺序排序。
2. **目标值**：数值需有限、非空。温度允许出现真实负值，不能把异常或负数全部自动归零；缺失值禁止隐式插值或填充。
3. **可用时间**：选择真实列时使用源时间；选择声明延迟时根据明确填写的天数计算。滚动验证和独立测试每个预测起点均检验：历史数据可用时刻不能晚于预测起点，预测目标时刻必须晚于最后历史数据可用时刻。**每小时数据延迟 24 小时发布时，不允许直接做未来 3 小时预测。**
4. **频率**：仅接受现有 `h/D/MS` 引擎明确支持的频率。源数据若是 1 分钟/秒/5 分钟，页面提示需独立可审计的重采样/聚合适配；当前不会只修改频率标签。若原始存在每小时缺口，也不自动填平。
5. **多实体**：按设备分别计算有效时间点和回测结果，任何一台入选设备历史不足或连续性不合格即阻断整个任务；建议先在 BI 收窄设备筛选。
6. **规模上限**：当前模型适配一次最多 200,000 条筛选后明细记录，超限明确提示。截断图表结果、前 1,000 行查询页或均匀抽样画像不改变真实训练范围。
7. **模型特征**：数据资产保留全部源字段；本版实际训练仅使用目标自身的历史。气压、风机电流、维护事件、工况及未来标签均不隐含进入模型，防止伪造多变量建模能力。

## 4. 时间序列切分与评估协议

所有训练、验证和独立测试都按时间顺序进行，无随机打乱；每台设备独立回测并输出序列维度结果。

对于每台设备，设历史最小长度 `H_min`、预测跨度 `h`、滚动窗口数 `W`、插件最少历史长度 `P_min`，所需连续观测至少：

`N_required = max(H_min, P_min) + 2 × h + W - 1`

以每小时采样、`H_min=24`、`h=3`、`W=3`、最近值/移动平均为例，至少需要 32 个连续小时观测。3 个滚动验证窗口位于独立测试窗口之前；最后 3 小时仅用于最终测试，不能参与模型选型。季节性插件的最短历史要求更高，并依据当前模型插件校验。

| 指标 | 单位/口径 | 使用注意 |
| --- | --- | --- |
| MAE（主） | ℃；平均绝对误差 | 直接判断每个预测步长的温差，推荐主指标 |
| RMSE | ℃；平方误差均方根 | 关注少量较大的温差 |
| ME | ℃；平均有符号误差 | 区分持续预测偏高还是偏低，保留物理单位 |
| Bias（兼容历史） | 相对比值；预测误差总和 / 目标绝对值总和 | 历史引擎的有符号相对偏差，目标接近零时不可计算 |
| WAPE | 比值 | 目标接近零或正负抵消时需审慎解读，不能单独判断模型可用 |
| MASE | 无量纲，和朴素基线相比 | 朴素差分尺度为零时应标为不可计算 |

输出至少包括：按预测步长（1/2/3）的误差、逐设备误差、验证窗口趋势、独立测试结果、与最近值基线比较、预测时刻及预测来源版本。当前运行器可输出相应记录和质量报告；独立的设备运行看板和业务告警阈值仍可继续扩展。

**可用性的判断建议**：MAE 不高于生产线可接受的温差门槛，并相对最近值基线有稳定改进，偏差方向无系统性漂移。门槛值需要由工艺/质量部门根据设备温控规格给出；当前不以随意指定的“准确率 95%”代替工程指标。负温度和接近零的目标应优先使用 MAE/RMSE。

## 5. BI 视图与训练数据的一致性契约

每个草稿冻结以下对象：

- `project_id`、通用 `asset_id`、底层源 `generic_version_id`、原始数据 SHA-256 和 Native BI 快照 SHA-256。
- `view_id` 及保存视图配置摘要；当引用已保存查询视图时，提取**明细行级筛选**，丢弃展示用 `group_by`、`metrics`、`limit`、`offset`、`order_by`；如果用户改变保存视图的版本或配置，则拒绝继续引用旧草稿。
- 原始字段名、筛选 JSON、筛选摘要 `selection_hash`、完整字段映射、频率/跨度/评估方案摘要 `plan_hash`。
- 生成训练集时写入已冻结输入的 SHA-256、规范化数据集 ID、快照哈希和来源 JSON。
- 运行记录写入唯一 `run_id`、任务配置摘要和数据集 ID；模型管理与血缘 API 可复查来源。

编辑后的 BI overlay 版本需要先成为新的不可变通用资产再进行字段画像。当前新工作流不暗中读取修改的临时副本、不合并两个不同项目的数据。

## 6. API 与 Agent 工具

API 前缀：`/api/v1/projects/{project_id}/modeling`。

| 方法 | 路径（省略前缀） | 作用 |
| --- | --- | --- |
| GET | `/assets/{asset_id}/profile?version_id=base` | 统计字段画像、候选角色、时间采样建议 |
| GET | `/assets/{asset_id}/suggestions` | 给出候选任务、执行状态与限制 |
| GET / POST | `/drafts` | 查询项目草稿 / 锁定源版本和行级筛选 |
| GET / PATCH | `/drafts/{id}` | 查看 / 修订未生成训练数据的草稿 |
| POST | `/drafts/{id}/preflight` | 全量选中行校验时间轴、可用时刻、插件能力 |
| POST | `/drafts/{id}/approve` | 明确人工确认映射和可用时间限制 |
| POST | `/drafts/{id}/materialize` | 生成具来源摘要的规范化训练数据 |
| POST | `/drafts/{id}/submit` | 入队现有预测执行器，保持同草稿重试幂等 |
| POST | `/drafts/{id}/reproduce` | 以同数据和配置建立独立、待审批的复现实验 |
| GET | `/drafts/{id}/lineage` | 汇总筛选、数据集、版本、训练任务与运行来源 |

API 接受结构化 JSON，字段白名单由 Pydantic 验证；不接受用户拼接 SQL、文件路径或运行命令。Agent 注册表增加：`modeling.profile.inspect`、`modeling.tasks.suggest`、`modeling.draft.inspect`、`modeling.draft.preflight`（只读），以及 `modeling.draft.prepare`（必须经写入授权）。Agent 只获取字段画像/有限聚合元数据，自动建模训练仍要由用户完成审核。

数据库新增 `project_model_drafts`、`project_model_run_sources`，沿用原有项目库。旧预测视图与任务接口保留；项目模型清单统一展示历史来源和新通用建模来源。

## 7. 验收条件、实测与边界

自动化：真实项目导入与通用发布（仅 BI 依赖通过测试双身替代）、来源与视图摘要校验、同源两次筛选建模、人工审批、数据集生成、真实基线模型执行、独立克隆复现实验输出一致、跨项目隔离、分钟级/频率不符阻断、时间延迟泄漏阻断、已发布数据篡改拒绝、Agent 权限契约，以及本机现有 Chromium 的确认抽屉操作。

生产上线前必须在具备 DuckDB、PyArrow、Perspective 离线构建资源的目标环境再验收：真实 BI 上传/查询/保存视图/返回、数据 overlay 版本发布、浏览器刷新恢复、大文件读写性能、任务并发与异常断电。当前版本仍是本地单用户研发模式，未完成企业多用户身份认证、权限审计、百万级训练数据适配和分钟级聚合转换。系统不得因此对用户承诺已支持全部工业预测任务。

## 8. 后续插件复用方向

分类、异常检测、机理学习与可信实验优化统一引用 `project_id → asset_id/version → selection_hash → field_map → evaluation_spec → dataset_snapshot → run_id`。后续优先补两类独立能力：**可审计重采样适配**（分钟/秒数据的聚合口径、桶完整率、可用时间按桶结束计算）和**多变量/事件模型插件**（按观测时点区分历史可用特征与未来未知输入）。原始文件导入、字段画像、BI 版本与任务审批无需重做。

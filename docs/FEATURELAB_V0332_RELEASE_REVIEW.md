# TimePilot v0.33.2｜可信模型评价、固定基准与覆盖交付审阅

## 1. 范围与基线

基线为 **TimePilot v0.33.1 FEATURE_WORKBENCH_FULL_SOURCE**，本次只修改直接可替换的相对路径源码及文档。未修改数据库 Schema，未增新运行依赖。保留历史 PIT 审核、特征工厂、模型评价、原生 BI、任务与项目隔离。目标是对普通静态回归、二分类与多设备时间预测提供同折对照及可审计的训练验证隔离。

## 2. 主要修复

1. **静态监督支持**：`TaskSpecV2` 增加 `kfold / stratified / group`，要求 `static_independence_confirmed` 明示确认。静态任务不伪造预测时间及标签时间，生成不同于时间任务的 `static_row_local` 安全证明。
2. **设备/批次隔离**：实体键必须与数据契约完全一致，不能通过删除任务中的实体 ID 绕过组隔离。同一设备或批次的样本禁止随机 K 折；使用 GroupKFold 或满足条件的 StratifiedGroupKFold。
3. **数据泄漏阻断**：静态监督只允许逐行算子，拒绝目标标签、时间列、编号、未确认或受限列、跨行窗口与未受控的派生嵌套。时间监督保留原 PIT 门禁、设备分区和真实标签可用时间检查。
4. **真实训练行审计**：时间监督外层训练折按 `label_available_at <= training_cutoff` 二次过滤，更新持久化折清单中的实际训练样本数、行索引 SHA256、验证样本及折类型；以前只记录预过滤样本的口径已纠正。
5. **同折模型对照**：每个验证折使用相同训练与验证行、相同随机种子及模型，对比 `raw_only / with_features / selected_features`。缺失值填充、标准化、特征筛选均在训练折拟合。回归报告 MAE / RMSE；二分类报告 AP、Recall、Precision、误剔率及混淆矩阵数据，阈值暂固定 0.5。
6. **特征筛选稳定性**：报告每项特征的跨折入选次数、训练折选择集合的 pairwise Jaccard、一致性区间和同折配对增益；不从验证标签挑选候选或调参。
7. **受控搜索边界**：静态及 `grouped_time` 任务禁止开启尚未实现独立内层验证的候选搜索；避免在外层验证数据中优化配方。
8. **工作台集成**：在 v0.33.1 实际工作的 `feature-workbench-ui.js` 中新增监督评价表单，自动列出与契约匹配的 K 折、分层、分组与时间验证方式；仅用户明确确认才绑定模型评价。界面只展示经过相同物化产物 ID/SHA256、项目内数据库记录及成功任务证明的模型对照和筛选稳定性。
9. **版本兼容**：原有时间监督 TaskSpec 的 `model_dump` 不新增静态确认字段，从而尽量保留历史持久化的任务摘要及来源 SHA；契约 JSON Schema 已重新导出。

## 3. 固定数据与观察值

三套测试集均为确定性生成的 **合成数据**，用于校验数值计算正确性与泄漏防护。其统计改善在生成机制中预设，不能当作真实工业应用的算法收益。

| 场景 | 文件 | 记录数 | 验证切分 | 基线 | 同折增强对比（3 折均值） |
|---|---|---:|---|---|---|
| 静态回归 | `static_regression.csv` | 270 | KFold(3)，seed=3302 | MAE 3.20535 | 新特征相对基线 MAE 下降 **2.75436** |
| 静态二分类 | `static_binary.csv` | 360 | StratifiedKFold(3)，seed=3302 | AP 0.35560 | 全特征相对基线 AP 增加 **0.30868** |
| 多设备时序预测 | `multi_device_time.csv` | 480，6 台设备 | 时间递增滚动验证(3) | MAE 1.85015 | 新特征相对基线 MAE 下降 **1.26237** |

备注：上述改善为 `paired_comparison` 默认 `with_features` 对 `raw_only` 的同折差值，**不是**跨折显著性推断、也不是筛选特征必然有效。用于再现测试的完整 SHA256 写在 `tests/fixtures/featurelab_v0332/MANIFEST.json`，每次加载会验证内容一致。三个基准的训练折选择一致性 Jaccard 均为 1.0，这与合成生成函数高度稳定有关，不能推断实际产线的选中特征同样稳定。

## 5. 已知限制和后续工作

- 自动特征搜索仍有基于**全量无监督质量画像**而确定候选池的过程。只要候选集合或算子参数曾利用验证集分布调整，就不能将固定外层验证结果称为完全无选择偏差的生产外推证据。严谨比较需在独立最终测试集或独立时间窗上锁定候选配方，必要时实现内层折生成。当前版已保证模型拟合、特征筛选和受控自动搜索的核心门禁，但尚未完成对全量画像候选池影响的全面量化。
- 目前回归/分类单任务中标签字段需具备已确认数值语义；普通字符串分类标签要先在数据管理定义受控类别映射。
- 分组 K 折要求每折满足两类样本和最低样本数，组过少或类别极度不平衡时会拒绝评价。分组时间切分对独立批次需要可分离的历史区间；重叠过多时可能无法形成全部验证折。
- 特征构造对静态监督只开放安全的行级算子；同设备历史窗口须经时间监督 PIT 门禁，不能通过静态模式混用。
- 前端自动分析阶段推进仍包含浏览器轮询的历史机制，完整后台调度属于后续迭代。
- 真实 DuckDB、macOS 本机浏览器及企业业务标签的正式验收仍需完成；不存在经验证的工厂性能提升数据。

## 6. 用户要求的直接覆盖交付

交付文件：`TimePilot_v0.33.2_DIRECT_OVERLAY.zip`，ZIP 根目录直接是 `src/`、`tests/`、`contracts/`、`docs/`、`frontend/`、`scripts/` 等**相对于原项目根目录**的文件。仅包含 v0.33.1 → v0.33.2 修改或新增的文件、对应的 `docs/RELEASE_MANIFEST.json`，**不含安装、自动下载或迁移脚本**。

1. 停止 TimePilot 进程；保留并备份已有源码与 `TIMEPILOT_HOME` 数据目录。
2. 打开 ZIP，选择里面的目录和文件，复制到原来 `timepilot/` 的根目录，并接受**覆盖同名文件**。无需运行任何安装脚本，不创建新的环境，也不删除数据库。
3. 原有项目须基于交付的 v0.33.1；若有用户自行修改过的源码，先比对差异再覆盖。发布清单按该完整基线生成，混合源码会被严格校验阻断。
4. 在原项目的现有 Python 环境执行：

```bash
bash TIMEPILOT.sh source-check
python -m pytest -q tests/test_featurelab332_fixed_benchmarks.py tests/test_featurelab332_real_duckdb.py
node --test frontend/native-bi/tests/featurelab332_supervision.test.mjs
bash TIMEPILOT.sh
```

`tests/test_featurelab332_real_duckdb.py` 必须实得 **3 passed**，不可把 `skipped` 当作通过。`source-check` 可用来检查相对于发行版是否存在混合文件。默认不修改运行时数据库结构。

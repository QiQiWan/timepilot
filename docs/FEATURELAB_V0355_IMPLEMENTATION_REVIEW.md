# TimePilot v0.35.5｜自动研判、特征价值评价与模型结果解释

## 1. 改造范围与设计原则

本轮以 v0.35.4 为基线，集中建设统一分析工作台的证据展示。统计质量、特征计算质量、统计信息变化、监督模型效果分别展示，均由既有数据画像、候选质量报告和正式模型评价得到。无模型 API 时可以完成数据质量及特征质量研判。

正式特征计算、监督模型评价、发布和报告归档仍需现有权限与必要人工确认。自动研判接口为只读操作，不创建或修改模型实验，也不根据标签直接改变原始特征定义。

## 2. 实现清单

| 模块 | 本轮改造 | 输入与可信边界 |
|---|---|---|
| `feature_insights.py` | 确定性研判、质量汇总、信息变化、三组模型同折对照、稳定性及消融摘要 | 来源 SHA256、契约修订、已计算候选、核验的评价报告 |
| `feature_lab_v2_api.py` | `GET /workspace/insights?asset_id=&version_id=` | 项目/操作人权限、来源字节有效性、会话与契约一致性 |
| `feature_auto_delivery.py` | 核验通过后，返回特征组消融与泛化留出等摘要 | 对齐数据库持久化报告哈希和模型任务执行证据 |
| `feature_auto_analysis.py` | 导出 Markdown 时复用研判结果 | 无模型结果时明确写明没有可信收益结论 |
| `analysis-insights-ui.js` | 原生工作台的自动研判与三方案对照、证据折叠、只读刷新 | 前端不产生统计值、模型评价数值和 SHA256 |
| `analysis-workspace.js` | 将研判固定在数据统计与特征候选之间 | 同一项目、同一数据资产及版本上下文 |
| `analysis-insights.css` | 三卡片及模型对照的响应式样式 | 不新增前端框架 |

本轮继续复用 v0.35.4 的上传发布后自动画像和最多 16 项受控候选预览。仅在 `feature-lab` 已确认标签、确认训练验证协议且正式物化并完成同源模型评价后才显示指标对照。

## 3. 证据与指标口径

- **数据质量**：画像的缺失率；默认展示缺失率不低于 10% 的前 3 项及可追溯字段 ID。阈值用于提示，不代表字段应自动删除。
- **特征质量**：`quality_rows` 中 `recommended / review / exclude / unverified` 数量。质量通过只表示满足计算与覆盖率规则。
- **特征统计信息**：实测标准差是否为零，仅作为分布变化描述；相关冗余、信息增益和预测有效性不能由标准差直接得出。
- **模型收益**：只从同源 `mode=supervised` 的持久化评价得到。回归展示 MAE，二分类展示 AP，辅助指标若有完整折记录可显示 RMSE / Recall / FPR。原始字段、全部特征、筛选后特征必须使用同模型、同验证折。
- **对照约束**：至少 2 个完整配对折，原始、全部候选及筛选后三组均具有相同折上的有限指标。记录的平均改善量和改善折数必须与逐折原始指标一致；缺折、非有限值或口径冲突时隐藏三方案指标并显示“证据不足”。只有正向均值和足够多的正向折同时满足时才使用“存在改善迹象”的表述。
- **训练稳定性**：Jaccard 与逐折入选频次仅说明选中一致性；特征组消融仅说明模型敏感性，均不证明因果关系。
- **适用边界**：全源数据画像可能参与候选搜索；即使同折结果有改善，也需要在独立最终测试集及真实工业数据上验收。

每条研判存放 `evidence.kind`、`evidence.path`、`source_sha256`、`contract_revision`；模型证据还包含 `evaluation_id` 和 `artifact_sha256`。

## 4. 交互与回退

1. 数据发布及自动分析完成后，工作台先显示已有质量结论，再填充特征统计结果；无需另开“查看”“继续”跳转。
2. 点击“查看数据质量/自动特征”仅滚动定位当前工作台区域，不改变当前资产和版本。
3. 未配置大模型 API、没有已确认标签或尚未计算模型时，仍可查看质量和统计观察。模型区域明确说明等待的条件，不展示预测收益数字。
4. 切换资产/版本后，通过当前数据分析上下文重新请求研判；旧数据来源的异步响应会被忽略。
5. 失败时只显示可恢复提示，不使用推测值填充图表或指标。
6. 已有手工特征构造、高级算子、tsfresh/Featuretools 和模型评价入口保持不变。

## 5. 测试与验收

自动测试：`tests/test_featurelab355_evidence.py`、`tests/test_featurelab355_api.py`、`frontend/native-bi/tests/featurelab355_insight_ui.test.mjs`；相关 v0.35.4 旧路由与模型评价测试继续运行。浏览器使用系统 Chromium 进行隔离的 DOM 组件测试，不下载额外浏览器。

由于当前环境未安装 DuckDB / PyArrow，真实 Parquet 物化及 Perspective 表格和图表仍需 Mac 本机完成；不能将这项检查标记为通过。运行 `python scripts/featurelab355_acceptance.py` 将在既有环境检查源码、Python、Node 和物理依赖并打包日志；它不安装依赖。

### 需要现场确认的场景

- **无标签：** 上传并发布，数据质量、特征质量、统计信息均可展示；预测收益不得出现数字。
- **有标签但未评价：** 标签确认后，模型状态为待正式物化与监督评价；不自动训练。
- **评价完成：** 原始字段、全部候选与筛选后特征三组指标可逐折复核，报告及 BI 绑定同一数据版本。
- **来源变更：** 同长度源文件篡改、字段契约修订或资产版本切换均应阻断旧证据。
- **模型异常：** 关闭大模型 API 或模拟超时后，确定性规则分析保持可用。
- **可视化：** 在 Mac 本机 Chrome 中检查刷新、后退、长页面与移动宽度下的组件排列、点击定位及真实图表一致性。

## 6. 未闭合的能力

当前 v0.35.5 可解释的是**已实际计算的质量、统计结果以及受控的模型对照**。它尚未完成全任务的自动模型训练、统一多字段 BI 仪表盘、独立盲法最终测试集、真实工业业务收益评估，以及无人工审批的正式物化（正式物化必须保留审批）。这些不应以本轮通过的模拟测试替代。

## 7. 最终定向测试与现场验收说明

本轮新增两类负面测试：缺失筛选方案的某一折指标、报告中的改善折数与真实逐折结果不一致；这两种情况均应拒绝展示模型对照表。正式测试数量与运行环境记录在 `reports/featurelab355_acceptance/ACCEPTANCE.md`。

发布包只有原生源码和配置，未包含编译好的 Perspective 前端资源；真实 Mac 上 DuckDB、PyArrow 与 Chrome 端到端检查必须独立执行。

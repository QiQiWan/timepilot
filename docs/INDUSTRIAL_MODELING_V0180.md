# TimePilot v0.18.0｜工业建模统一契约、执行接口与验收说明

## 1. 本版交付边界

本版在 v0.17.0 的“项目 → 通用数据资产 → 正式 BI 行级筛选 → 建模草稿 → 审批 → 冻结训练集 → 运行 → 评估/复现”基础上，加入三项实际执行能力：

1. **分钟/秒原始观测到小时/日的显式聚合**。按设备、时间桶保存每桶的原始记录数、预期记录数、覆盖率、窗口起止、数据可用时刻及 SHA-256。原始记录和派生快照分别保留。出现重复周期、未对齐采样、缺少整桶、桶内工况切换等情况时拒绝聚合，禁止静默补值。
2. **多变量历史预测插件** `historical_exog_ridge`：把已确认的温度目标历史、其他传感器滞后项、维护事件和工况哑变量组合成直接多步岭回归；严格使用预测起点之前可用的特征。延续独立测试与滚动回测。未来尚未观测到的变量不作为模型输入。
3. **质量不良二分类插件** `binary_logistic`：决策时刻的数值特征经 L2 正则的逻辑回归生成风险概率；依时间先后划分训练/验证/测试，训练集做类别平衡，**仅验证集选择阈值**，独立测试集输出 TP/FP/TN/FN、召回率、精确率、误剔率、准确率。未达到审核召回率下限的结果只保留研究记录，拒绝在线推断建议。

维护事件、工况和物理约束已进入统一 `modeling_contract`；约束仅执行工程师明确提供的目标上下界和最大单步变化阈值。异常检测及可学习的机理动力学尚未接入实际执行插件，任务建议标识为不可运行。系统没有产线自动剔除接口。

## 2. 数据流与目录

`项目资产`（完整源列、不可变版本） → `Perspective 已保存视图`（冻结数据版本与行级过滤） → `项目建模草稿`（字段映射、插件、时间契约） → `预检查`（全量行级筛选、无泄漏） → `审批` → `模型数据集`（observations.csv + manifest.json + resampling_audit.json + modeling_provenance.json） → `任务队列` → `分类/预测插件` → `运行质量` → `模型管理/审计 API`。

固定训练的来源：`source.sha256`、`selection_hash`、`plan_hash`、`snapshot_sha256`、`resampling_audit_sha256`、`task_sha256`、模型文件哈希。已保存 BI 视图的透视、排序、显示采样行和分页不影响训练行集；查询视图只复用行级筛选。训练数据中 `timestamp`、`available_at` 必须有 UTC 时区；分类额外要求 `label_available_at`。

读取统一资产和既有预测引擎的方式不变；旧的 `TaskSpec`、`DatasetManifest` 字段保留默认值，旧无特征模型仍可执行。项目级授权边界沿用既有项目目录；本地单用户部署没有企业级多用户登录授权。

## 3. 字段、时间、频率与审计

| 字段或选项 | 规则与实际结果 |
| --- | --- |
| `time` | 可解析的真实日期时间；普通整数步骤序列不能冒充物理时间戳 |
| `entity` | 设备编号；为空时明确采用单序列；多设备先分组后计算 |
| `target` | 连续预测时为可转换的数值列；分类时为已确认的原始二分类标签列 |
| `observed_features` | 至多 32 个明确选择的数值输入，转换后为 `obs_01..`，来源映射记录在审计中 |
| `availability_policy` | `source_column`（逐行真实可用时刻）或 `declared_lag`（人工确认延迟天数）；不允许未确认时直接训练 |
| `feature_available_at` | 可逐个特征声明真实可用时间字段；若晚于主时间，则提升该行 `available_at`，分类需早于决策时间 |
| `batch` | 分类场景的批次号；同批次不得横跨训练、验证和测试，否则阻断 |
| `resampling.source_period_seconds` | 声明原始采样间隔；可选 1、30、60、300、900 秒等正整数，且必须整除目标桶 |
| `resampling.aggregation` | `mean/last/min/max`，同一统计规则用于目标和普通数值特征；不生成未观测数据 |
| `resampling.min_coverage` | 实际观测个数 / 桶内理论周期个数；低于用户确认阈值立即阻断；默认 100% |
| `resampling.require_complete_timeline` | 默认启用；整小时或整日缺口阻断；未经过审批不执行补齐/插值 |
| `event` | 源事件列、触发值、事件是否跨窗重置；可生成 `event_flag`、`event_age_steps` |
| `regime` | 工况类别展开为 `regime_01..`；每个聚合桶内工况必须唯一 |
| `mechanism` | 物理上下界、最大每步变化，工程证据参考和 `block/warn`，无参数时不推测约束 |
| `classification` | 正负原始取值、标签成熟时刻或延迟、判断节点、召回率下限和按时间切分参数 |

每个完整桶从 `[bucket_start, bucket_end)` 读取数据，计算 `coverage = input_rows / expected_rows`，派生目标可用时间为 `max(源记录 available_at, bucket_end)`。在 `mean` 聚合时，模型无法在桶结束前看到整个桶的均值。UTC 小时边界、按源时区的日边界会写进审计；夏令时产生长度不固定的日桶会阻断。

**示例：** 56 小时、每分钟 1 条的设备记录共 3,360 行，经用户确认 `h`、每桶 60 条、覆盖率 1.0、`mean` 后生成 56 行规范化数据；审计每桶记录 `60/60`。原始资产保留 3,360 行。若缺少第 91 个分钟记录，所在桶为 `59/60`，默认规则阻止训练。

## 4. 预测插件与验证协议

插件 ID：`historical_exog_ridge`。一个训练样本输入目标历史最近 3 个值、3 步均值，及每个已确认特征的最近值与 3 步均值。对预测步长内的各步分别拟合带 L2 正则的岭回归，系数和标准化统计量一起写入模型 JSON。仅支持月（MS）、日（D）、小时（h）规范化数据。默认至少 24 个历史点，但整个滚动验证需要更长数据；系统预检查按实际预测跨度、窗口数计算。

三个重要规则：

- 训练内部构造每个历史窗口时，不读取当时尚未可用的数据；若指定维护事件重置，则丢弃跨维护事件的训练窗口，最终正式模型重训也执行相同规则。
- 滚动验证、独立测试和最终未来预测均检查已确认物理上下界与单步变化。约束超限时按 `block/warn` 处理；当前 `warn` 不提供物理修正预测功能。
- 不读取未来外生变量，不自动推断未声明的工况、事件或采样间隔。不同设备独立建模与测试。

预测沿用 MAE/WAPE 主指标和 RMSE/MASE/ME/Bias 等评估记录。MAE、RMSE、ME 使用目标的物理单位，其他比值/比例按其定义呈现。此模型是可解释的基准型岭回归；不将结果表述为工业基础模型或机理学习器。

## 5. 分类插件与质量指标

插件 ID：`binary_logistic`。分类输入为明确映射的每条产品/每个节点的数值特征快照。系统验证所有特征在决策时刻已知、标签时间没有越界、正负类有足够样本、批次不跨越数据切分。标签成熟时间用于决定它能否进入训练和验证，测试集仅包含已成熟标签。训练、验证、测试按全局决策时间轴前推，不进行随机打乱。

训练阶段按正负类别加权、进行标准化、拟合带正则的逻辑回归。验证阶段从模型概率阈值中选择满足 `min_recall` 且误剔率最小的阈值；测试阶段仅使用该固定阈值计算独立指标。测试召回率未达到下限时标记 `review_required`，不会返回“可用于生产剔除”的结论。独立测试的业务阈值仍需在真实厂内验证，尤其要评估低不良率时的误剔数量和分布漂移。

指标定义：

- `recall = TP / (TP + FN)`：不良件检出率，重点关注漏检。
- `false_positive_rate = FP / (FP + TN)`：正常件被误判高风险的比例。
- `precision = TP / (TP + FP)`：预警件中真正不良的比例。
- `accuracy = (TP + TN) / N`：仅辅助展示，不作为低基率不良检测的主要指标。

分类推断 `/score` 只提供**研究决策支持**：逐条声明 `decision_time`、`features_available_at`、设备和审核时一致的数值特征，经审核后输出 `probability`、`risk_flag` 和“人工复核”建议。模型文件必须通过哈希校验，训练质量必须为 `passed`；如果模型使用事件/工况上下文特征而请求无法提供同样的上下文转换，将直接拒绝评分。没有 PLC 或产线控制动作。

## 6. 用户操作与页面状态

1. 在项目中导入、审核并发布数据，然后进入正式 BI，通过筛选保存希望分析的设备和时间范围。
2. 点击“从当前数据建立模型”，系统建议时间字段、实体、目标、采样情况。选择“趋势预测”或“质量不良二分类”。
3. **预测**确认目标、设备、可用时间、历史特征，若分钟级则勾选重采样并确认原周期、聚合方式和覆盖率；可展开维护事件、工况及物理约束。**分类**确认判断时刻、标签正负取值、标签成熟时间、可用数值特征和最低召回率。
4. 保存草稿后进行预检查。查看源记录数、筛选行数、训练行数、物理约束与时间切分；不通过时页面展示阻断原因。
5. 审批后物化只读训练集，提交运行；在项目模型管理页查看运行状态、评估、来源与复现实验。

UI 当前没有对每列特征可用时间的逐项图形选择器；这一高级字段契约已可通过受控 API 配置。`anomaly_detection` 与 `mechanism_learning` 是后续插件槽位，现阶段不允许提交真实运行。

## 7. HTTP API 与 Agent 工具

以下 API 均以当前项目 `pid` 为作用域。实际 URI 以 OpenAPI schema 为准，所有写入均进行 Pydantic 校验；不允许 SQL、任意文件路径或代码片段。

| 方法 | URI（省略共同前缀 `/api/v1/projects/{pid}/modeling`） | 作用 |
| --- | --- | --- |
| GET | `/assets/{aid}/profile` | 字段画像和源数据范围 |
| GET | `/assets/{aid}/suggestions` | 可执行状态与插件建议 |
| POST | `/drafts` | 创建冻结来源、字段映射、任务类型及评估协议草稿 |
| PATCH | `/drafts/{did}` | 乐观版本号更新（变更则原审批失效） |
| POST | `/drafts/{did}/preflight` | 全行统计、聚合审计和时序/分类泄漏检查 |
| POST | `/drafts/{did}/approve` | 对草稿版本与数据可用时间人工审批 |
| POST | `/drafts/{did}/materialize` | 保存不可变数据与来源/桶审计哈希 |
| POST | `/drafts/{did}/submit` | 入队适配的预测或分类运行器 |
| GET | `/drafts/{did}/audit?offset=0&limit=50` | 分页查看每桶审计与源哈希 |
| GET | `/drafts/{did}/evaluation?offset=0&limit=100` | 分类混淆矩阵、指标、逐条概率或预测误差 |
| GET | `/drafts/{did}/lineage` | 查看从源版本到模型运行的血缘 |
| POST | `/drafts/{did}/score` | 已审核二分类模型的受控概率推断 |
| POST | `/drafts/{did}/reproduce` | 克隆同一数据/筛选/方案后独立审批和运行 |

Agent 白名单增加 `modeling.draft.lineage`、`modeling.draft.audit`、`modeling.run.evaluation` 等只读工具；创建草稿需受控动作和人工确认。Agent 不允许跳过审批直接训练，不经用户允许向模型传送完整工业原始数据。

## 8. 独立测试与实际已知限制

自动化场景在 `tests/test_industrial_modeling_v018.py`：

- 56 小时分钟数据逐桶审计、多特征训练、维护事件与工况和不可变 SHA 校验。
- 漏掉一条分钟记录时强制拒绝无证据的自动聚合。
- 真实逻辑回归分类训练、标签成熟时间、前推切分、验证阈值、独立测试、同方案克隆重复预测。
- 不同项目隔离、无效标签契约和未来传感器阻断、在线推断严格字段和时间校验、模型文件被改写后的哈希拒绝。
- 已确认维护事件的排除跨窗规则同时应用到最终重训。
- UI 可使用本机已有 Chromium 运行测试（无需下载浏览器）。

**部署边界：** 本发行包为完整 Python/JS 源码，不附加已编译 Perspective JS/WASM；需要在目标机器执行离线资源构建/完整浏览器验收。本地测试中通用 BI 的查询可使用测试适配替身，不能将这些结果表述为生产环境已完成原生 BI 验收。当前模型没有跨设备泛化评估、实时流处理、分钟级直接预测插件、动态机理识别学习、产线自动决策，也未提供企业多用户权限/公网安全加固。大规模单次物化仍有 20 万条**源筛选行**上限；发布前需评估实际设备数据规模、内存与耗时。

## 9. 运行与检查

推荐 Python 3.12，复用当前环境。先备份已有 `TIMEPILOT_HOME`，不要直接在唯一业务库副本上做版本迁移测试。

```bash
# 在源码根目录
bash TIMEPILOT.sh source-check
PYTHONPATH=src python -m pytest tests/test_industrial_modeling_v018.py -q
PYTHONPATH=src python -m pytest tests/test_modeling_workflow_v017.py tests/test_modeling_browser_v017.py -q
node --check src/timepilot/static/modeling-ui.js
bash TIMEPILOT.sh check
# 如正式 BI 资源尚未构建，在具有本机依赖的构建机上：
bash TIMEPILOT.sh build
```

目录内保留所有 v0.17.0 兼容测试；版本升级不修改用户原始数据。完成目标环境的原生 BI → 保存视图 → 建模 → 审计 → 重启后复现测试后，再考虑对正式产线推广。

# 可靠运行与故障恢复设计

## 已实现

- **持久化状态**：每条任务在 SQLite 数据库中记录 id、status、stage、progress、attempts、worker_id、lease、error 和时间戳。
- **原子领取**：Worker 基于条件更新领取排队任务，避免同一时间被两个 Worker 正常领取；失效租约可回收。
- **心跳**：独立后台线程定期延长租约，避免运行中被其他 Worker 误领。
- **阶段检查点**：validate、backtest、forecast、quality 各阶段写入 JSON 产物和 SHA256 回执；恢复时逐一校验。
- **细粒度缓存**：对每个 series、模型和滚动预测窗口保存预测记录与 SHA256，重试时复用已验证的结果。
- **显式失败记录**：异常进入 `failed` 状态，保留错误类型、可读消息、精简堆栈与运行事件，不进行无限自动重试。
- **取消**：排队时可立即取消；运行中设置取消请求，模型在调用边界检测并停止后续步骤。
- **资源预检查**：数据验证前检查可用磁盘空间（默认至少 0.5 GB）。
- **幂等产物写入**：使用临时文件写入并以 `os.replace` 原子替换结果文件。
- **路径约束**：所有 run_id 为 UUID；重新加载模型的相对路径必须保留在该任务存储目录下。

## 重要限制与升级路线

1. **SQLite 单 Worker 模式**：当前经过测试的是单实例本地 Worker。生产多机应采用 PostgreSQL 并验证并发租约与抢占；同时应使用数据库迁移方案。
2. **模型内中断**：当前无法强制中断一个不响应的第三方模型 `fit`；需要 v0.2 子进程监督、超时强杀和 GPU 资源隔离。当前断点恢复在模型与阶段边界生效。
3. **预算**：`training_budget_seconds` 作为模型训练参数传递给插件，尚无硬限制全部计算的操作系统级资源配额；不能把这一参数视为容器资源限额。
4. **磁盘保护**：提前检查容量，若运行中硬盘突然完全耗尽，写入错误日志也可能失败。正式使用要加入预留应急空间、存储配额及自动清理策略。
5. **数据库与产物一致性**：本地单机模式下使用数据库和文件系统双存储，极端崩溃存在短暂不一致；回执校验帮助恢复。生产阶段引入 outbox 模式或事务化对象清单。
6. **缓存完整性**：模型训练过程中的插件内部 checkpoint 需要插件自己保证。当前缓存只能对已完成的预测结果和阶段产物进行复用。
7. **安全**：当前日志可能包含错误消息等业务元数据；正式系统需要脱敏、按角色访问审计和配置外部密钥托管。

## 运维建议

- `timepilot doctor --strict` 检查运行 Python 及插件状态。
- `timepilot inspect <run-id>` 查看结构化运行日志。
- 取消、重试都由运行状态接口管理，不直接删除目录。
- 任何正式测试应生成新的 `TaskSpec`、数据快照版本与独立评价协议，避免修改既有结果。

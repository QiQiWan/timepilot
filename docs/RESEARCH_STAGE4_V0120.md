# 第四阶段 v0.12.0：真实业务能力与受控自主建模

## 一、已实现与证据边界

- 真实文件：沿用工作簿候选发现能力，仅按真实字段结构生成待人工标注样本。未经专家审查的规则建议和模拟模型返回不能成为金标。
- 人工标注：支持逐工作表审核和 UTF-8 CSV 批量提交。模板中的 `suggested_*` 字段仅供参考；`roles_json`、`layout`、`confirmed_by_human=true` 和 `reviewer` 必须由人工明确填写。导入逐条校验来源哈希、字段、角色唯一性，全部通过预检后记录各自版本。
- 对照评估：提供固定 seed 的配对试验，每一案例由两个与真值审核员不同的复核者分别进行规则/模型会话，交叉平衡分组。冻结参考标注 SHA-256；真值有修订时禁止沿用旧方案。模型需显式启用并有实际 API 才可调用。
- 统计：记录真实提交修改字段数、会话耗时（包含空闲时间）、任务正确率和 API usage。配对尚未完成时不计算模型收益；完成后的差值仍是描述性统计，不保证因果效果。真实业务用户试验与模型费用必须由目标机执行得到。
- 预测：要求唯一来源、唯一统计口径、真实带时区的 available_at、无重复或缺失的连续月份。Last Value / Moving Average / Seasonal Naive / Lag Ridge 在相同滚动起点评估；逐窗口误差、候选失败、特征策略与报告 SHA-256 一起归档。
- 机理：可关联同一数据资产及版本的状态-控制-维修数据证据，进行一阶动力学参数辨识和留出验证。机理状态仍为研究候选，不能自动充当销量外生特征，不执行部署。

## 二、实测与未验证分离

新功能的自动测试采用**合成已知真值和模拟模型调用**检验权限、分组、记录完整性、转换和回归正确性。它们不能证明真实业务领域的人工修正量、模型成功率或 API 延迟与费用。已有年度 Excel 具有真实结构，现有人工金标与实际外部模型调用均需业务侧补充。

## 三、验收顺序

1. 导入真实 Excel，创建待复核队列，导出 CSV，业务专家独立完成角色、实体和统计口径标注。
2. 校验导入人工标签，建立配对方案并冻结哈希。两个复核者各自完成规则/模型任务；模型调用需提供真实有效的 API。
3. 查看完成配对数、实际修改量与耗时，按业务口径和工作表难度分层复核，避免对小样本做显著性断言。
4. 对具备真实发布时间的已审查资产构建预测实验，审阅模型失败情况和逐窗口误差，留存不可变实验报告。
5. 如需机理学习，上传真实有证据的状态、控制、维护事件数据，确认同资产版本并进行工程专家校核。没有实测状态与控制时保持 `no_mechanism_evidence`。
6. Mac 上执行 `bash TIMEPILOT.sh accept research` 与 `bash TIMEPILOT.sh accept research-browser`；对于原生 Perspective，另执行 `bash TIMEPILOT.sh accept native`。现有容器缺少完整 DuckDB/Perspective 的实机组合，不能据此声称 Mac 原生 BI 已闭环。

## 四、仍有必要继续完善的部分

当前 Python 本地模式尚无企业实名身份鉴别与审核签名；随机分组的两位审核人员标识只能构成操作记录，不能替代人事身份认证。A/B 人工计时包括浏览器空闲时间，若需要纯人工工时指标应增加专门的活跃时间测量与问卷交叉校验。复杂工况切换、维修状态重置的神经微分方程与 SINDy，以及硬超时 Worker 进程隔离仍在后续研究范围内。
